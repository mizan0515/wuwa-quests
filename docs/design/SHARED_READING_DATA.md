# 원문과 독서 화면의 공통 구조

두 자료집은 `src/lib/reading-kit`의 동일한 HTML 생성기와 CSS를 사용한다. 명조의 배포 소스에서는 `source/src/lib/reading-kit`에 둔다. `manifest.json`의 파일 해시는 양쪽의 구현이 같은 계약을 유지하는지 검사한다. 게임별 어댑터가 원자료를 읽고, 공통 생성기에 정규화한 자료를 전달한다.

## 정규화 자료

`public/reading-data/graph.json`은 `game-reading.v1` 형식이다. 원문 전체는 기존 자료 파일에 보존한다. 공통 목록에는 원문 URL과 블록 색인을 두고, 블록의 위치와 해시는 `sources/0.json`부터 `sources/f.json`까지 나눈다.

| 자료 | 역할과 연결 |
|---|---|
| sources | 원문 ID, 제목, 종류, 본문 URL, 블록 수와 색인 |
| blocks | 원문의 필드 또는 절·행, 문장 식별자, 길이, SHA-256, 해당 위치 URL |
| entities | 인물·지역·개념 등의 ID, 이름, 종류, 개별 본문 URL |
| evidence | 인용 구절, 원문·블록 ID, 해시, 자료명, 서술 주체, 원문 위치 |
| claims | 서술, explicit/attributed/inference 구분, 주체, 근거 ID 목록 |
| relations | 양쪽 대상 ID, 관계 이름, 성격, 연결 이유의 claim ID |
| events | 사건 제목, 확인된 시점, 설명의 claim ID, 묶음 안의 표시 순서 |
| clusters | 중심 대상, 질문, 주제별 claim 목록, 비교·과정·포함·시간 표현 |

명조는 원문 필드와 텍스트 식별자를, 스타레일은 문서·절·행·문자열 해시를 위치로 보존한다. 원문에 인용이 존재하는지 어댑터가 검증한다. 단어가 같은 전체 자료 색인과 사람이 문맥을 읽고 편집한 묶음은 각각의 범위를 유지한다. `events.order`는 화면 순서이며, 작중 시간의 선후는 `timeOrdered`와 원문 근거로 따로 표시한다.

## HTML 표현과 QA

공통 생성기는 주제별 절, 명칭이 있는 관계, 사건 흐름, 관점 비교, 포함, 단계·순환, 원문 읽기를 제공한다. 실제 근거가 있는 표현을 각 게임의 어댑터가 선택한다. 순환은 돌아오는 관계를 명시해야 생성한다.

`npm run qa:reading`은 템플릿 일치, 생성기 단위 검사, 구조화 자료 참조·해시 검사를 실행한다. 기존 전체 사이트 검증은 원문 문자열·링크·인용 위치를 대조한다. 실제 화면에서는 지역 → 인물 → 원문 → 복귀와 초기 임무 → 본문 흐름, 작은 화면의 넘침, 키보드 포커스를 확인한다.

이 파일은 내부 구현 문서이며 공개 본문과 검색 색인의 입력에서 분리한다.
