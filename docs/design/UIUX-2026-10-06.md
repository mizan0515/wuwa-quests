# 명조 퀘스트 자료집 UI/UX 개선

목표는 기억나는 제목·ID·대사로 퀘스트를 찾고, 장면과 선택지를 편안하게 읽는 것이다. 버전·임무 분류와 원문을 보존하면서 정보의 중요도를 크기·대비·정렬·여백으로 구분한다.

## 조사와 적용

2026-10-06 브라우저에서 실제 화면을 확인했다. 아래 관찰은 해당 사이트의 홈 화면 범위이며 사용성 실험 결과를 뜻하지 않는다.

| 참고 화면 | 확인한 특징 | 적용한 원칙 |
| --- | --- | --- |
| [사용자가 지정한 타임라인 스펙](https://ttaem00.github.io/cva-ttaempad-timeline-spec/index.html) | 따뜻한 종이색, 짙은 잉크색, 절제된 금빛 강조, 좌측 탐색과 중앙 읽기 영역 | 색상 체계와 읽기 중심의 정보 위계 |
| [Minimal Gallery](https://minimal.gallery/) | 일관된 그리드와 간결한 카테고리 컨트롤 | 반복되는 퀘스트의 정렬과 메타데이터 위치를 일정하게 유지 |
| [Recent](https://recent.design/?ref=godly) | 사이드 탐색, 작은 분류 컨트롤, 콘텐츠가 먼저 보이는 구성 | 목록의 버전 탐색을 압축하고 주요 임무 필터를 가까이 배치 |

Godly 주소는 확인 당시 Recent로 이동했다. Godly의 과거 화면을 확인했다고 주장하지 않는다. 참고 사이트의 이미지·문구·스타일 파일을 복사하지 않았다.

기존 목록은 상단 제목과 필터, 긴 탐색 목록 때문에 첫 결과를 확인하는 데 많은 공간이 필요했다. 상세 화면은 화자와 대사, 내부 자료 정보의 시각적 우선순위가 비슷했다.

## 최종 설계

- 종이색·잉크색·금빛을 라이트/다크 테마에 맞춰 정의한다. 제목은 가장 크게, 대사는 16px로, ID와 내부 자료 정보는 보조 정보로 표시한다.
- 목록 화면에서 버전은 압축된 탐색 그리드로 제공한다. 제목·ID, 버전, 임무 종류 필터와 주요 임무 바로 선택을 함께 둔다.
- 퀘스트 한 행 전체를 링크로 사용한다. 제목, 종류, ID, 장면 수를 일정한 위치에 표시한다. 결과 수와 버전별 수는 현재 필터를 반영한다.
- 필터를 URL에 보존한다. 검색 결과가 없을 때 조건 변경과 초기화를 제공하며 초기화 후 검색창으로 초점을 돌린다.
- 데스크톱 대사는 화자와 본문을 두 열로 정렬하고 모바일에서는 화자를 본문 위에 둔다. 선택지는 배경과 왼쪽 선으로 구분한다.
- Starlight의 검색·목차·모바일 메뉴·테마 전환을 유지한다. 전면적인 검색 재구현이나 새로운 런타임 의존성을 추가하지 않는다.
- 포커스 테두리, 폼 레이블, 결과 알림, 눌린 필터 상태, 모션 감소 설정을 지원한다.

## 검증 범위

- 전체 정적 빌드: 769개 HTML 페이지와 Pagefind 검색 인덱스 생성.
- 원문 보존: 766개 퀘스트의 97,860개 대사·선택지 문단 텍스트가 기존 페이지와 동일. 원본 TXT SHA-256 및 빌드에 복사된 TXT 바이트 동일.
- 목록: ID 검색, 조건 조합, 필터별 그룹 수, 결과 없음, 초기화, URL 조건 유지, 새로고침 후 복원.
- 실제 브라우저: 모바일 메뉴에서 버전 이동 및 메뉴 닫힘, 밝은/어두운 테마, 320px·390px 목록과 읽기 화면의 가로 넘침 없음.
- 키보드: 필터의 순차 이동과 3px 포커스 테두리, 검색 단축키, Esc 닫기 후 초점 복원.
- 읽기: 대사 번호 보기/숨기기와 장면 탐색. 전체 검색에서 ‘비단 등불 수레’로 대사 결과를 찾고 해당 장면으로 이동.
- Lighthouse 최종 검사: 밝은 모바일 목록, 밝은 데스크톱 읽기, 어두운 모바일 읽기 각각 접근성 100점 및 전체 감사 실패 0개. 어두운 읽기 검사는 실제 `data-theme="dark"`와 배경색을 함께 확인했다.
- 코드 검토: 구성·생성기·신규 컴포넌트·필터 상태·반응형 CSS를 직접 확인했다. 원문/매니페스트와 의존성 잠금 파일 변경 없음. `git diff --check` 및 수정한 JavaScript의 구문 검사 통과.
- 장면 제목 링크: 제목과 Starlight 래퍼의 글자 크기(20.8px)·줄 높이(32.24px)를 일치시켰다. 링크 아이콘은 17.2px로 표시되며, 짧은 제목과 320px 화면의 두 줄 제목에서 정렬·키보드 초점·장면 URL 이동을 확인했다.
- 정적 파일 내보내기: 기존 `deploy:files` 경로로 저장소 루트에 적용하고 빌드 결과와 바이트 단위 일치를 확인했다.

원본 TXT의 브라우저 다운로드 실행은 권한 거부로 확인하지 못했다. 파일 자체의 보존 검증과 실제 다운로드 완료는 구분한다. 자동 접근성 검사는 수동 화면·키보드 확인을 보완하며 실제 스크린리더 사용자 테스트를 대신하지 않는다.

## 로컬 실행

`source` 폴더에서 `npm ci --ignore-scripts`, `npm run build`, `npm run preview -- --host 127.0.0.1 --port 4321`을 실행한다. 빌드 서버의 기본 경로는 `/wuwa-quests/index.html`이다. `npm run deploy:files`는 로컬 저장소 루트에 정적 파일을 복사하며 원격 게시를 수행하지 않는다.

사용자 승인에 따른 공개 사이트 반영과 최종 검증은 [이슈 #5](https://github.com/mizan0515/wuwa-quests/issues/5) 및 연결된 PR에서 추적한다.

## 하단 브랜드 영역 추가

[ttaem.com](https://ttaem.com/)의 실제 푸터에서 로고·소개·연락처 영역을 확인하고, 사용자 요청에 따라 자료집 공통 푸터에 추가했다. 소개 문구는 “명조의 이야기 속, 당신이 찾는 한마디까지.”로 바꿨다. 원본 벡터 로고는 `/brand/assets/ttaem-cva-master.svg?v=bd59d1cb3c9e`에서 가져왔으며, 로컬 정적 자산으로 제공한다.

데스크톱에서는 로고와 소개를 나란히, 모바일에서는 세로로 배치한다. 320px의 밝은 퀘스트 화면과 어두운 목록 화면에서 로고 표시·문구·가로 넘침 없음·44px 링크 영역을 확인했다. 홈 링크 두 개는 `https://ttaem.com/`, 연락처는 `mailto:ttaem00@naver.com`이며, 키보드 이동 순서도 확인했다. [Pagefind 공식 지침](https://pagefind.app/docs/indexing/)에 따라 `data-pagefind-ignore="all"`을 적용해 푸터 텍스트와 이미지 메타데이터를 검색 처리에서 제외한다. 공개 반영과 검증은 [이슈 #7](https://github.com/mizan0515/wuwa-quests/issues/7)에서 추적한다.
